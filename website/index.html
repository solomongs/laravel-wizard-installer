20i

Settle in on StackCP.

Use a 20i Linux hosting package with PHP, MySQL, and a configurable document root.

20i help centre↗
  1. 1

    Choose the right PHP version

    In StackCP’s PHP configuration, choose the version your Laravel project requires. The installer package itself needs PHP 8.1 or newer; your project may require more.

  2. 2

    Create your database

    Create a new, empty MySQL database and save its exact database name, username, password, and server hostname. Use the hostname shown in StackCP.

  3. 3

    Upload the prepared project

    Upload the developer’s deployment bundle. It must include vendor/, built frontend assets, and the generated installer files.

  4. 4

    Point your domain to the public folder

    Change the document root to the Laravel project’s public/ directory. Enable HTTPS, then visit https://your-domain.example/install.php.

cP

A familiar cPanel path.

Your provider must support the project’s PHP version and a safe public document root.

cPanel documentation↗
  1. 1

    Check MultiPHP Manager or Select PHP Version

    Select the required PHP version and enable missing extensions listed by the installer. Your host may name these screens differently.

  2. 2

    Use the MySQL Database Wizard

    Create a new, empty database and user, then grant that user privileges on the database. Copy full names, including any account prefix.

  3. 3

    Keep application files outside the public folder

    Upload the prepared project to a private directory. In Domains, point the document root to its public/ directory if your provider allows it.

  4. 4

    If the main domain root is fixed, ask your developer

    Your developer must prepare an adjusted public entry point while keeping .env, vendor/, and application files outside public_html/. Then enable HTTPS and open /install.php.

Check the essentials.

Compatibility comes from server capabilities, rather than a control panel’s name.

Read the requirements↗
  1. 1

    Ask your host about PHP support

    Confirm your Laravel version’s PHP minimum, required extensions, writable private storage, and MySQL or MariaDB access.

  2. 2

    Protect the Laravel application directory

    Serve only the public/ folder. If that is impossible, ask a developer to create a safe split layout before uploading.

  3. 3

    Upload a complete deployment bundle

    SSH and Node.js on the server are optional when your developer includes installed production dependencies and built assets.

  4. 4

    Run checks before entering settings

    Enable HTTPS, open /install.php, and use the private token supplied by your developer. Fix any blocked check before continuing.

i

Plain-English tip: The document root is the folder visitors can see. For Laravel, that should be the public/ folder. Your application secrets belong outside it.

A FEW GOOD QUESTIONS

Less guesswork.
More confidence.

Useful answers before you upload.

Do I need SSH or Composer on my hosting?+

No, if your developer prepares the complete project before upload. Composer dependencies, built assets, and installer preparation happen on a developer workstation or in CI. The website owner then uses the browser wizard.

Can it install any Laravel website?+

It is a reusable installer package for Laravel projects, not a universal server provisioner. The project and hosting still need compatible PHP versions, extensions, database privileges, and storage. Projects requiring persistent workers or special services need separate hosting support.

What happens if a check fails?+

The installer shows the failed check and practical next steps. For example, you may need to change PHP versions, enable an extension, correct a document root, or make a required directory writable. Fix the problem and check again before continuing.

Where do I get my database details?+

Create the database in your hosting control panel. Save its full database name, assigned user, password, and host address. cPanel often adds an account prefix to names. On 20i, use the database hostname shown in StackCP rather than assuming localhost.

Does it create an administrator account?+

Only when your developer implements the project-specific setup hook. Different Laravel applications use different account tables, roles, and authentication. The installer does not assume one universal administrator structure.

Can someone run the installer again?+

Setup requires the private token, and successful completion writes a permanent installation lock. Keep HTTPS enabled, protect the private application directory, and never publish the setup token. Reinstallation is a deliberate developer operation, not a public button.

Can I try this demo with real credentials?+

No. This documentation website is a simulation. It has no credential fields and never connects to your hosting or database. Enter real details only in the prepared installer hosted on your own secured domain.
